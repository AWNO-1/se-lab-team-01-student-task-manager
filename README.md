## 📖 نبذة عن المشروع (Project Brief)

مشروع تطبيقي مصغر تم تطويره كجزء من المتطلبات العملية لمقرر **هندسة البرمجيات (المستوى الرابع - تقنية معلومات)**.
يهدف المشروع إلى حل مشكلة تشتت الواجبات والمهام الدراسية ومواعيد التسليم لدى الطلاب الجامعيين، من خلال توفير منصة ويب مركزية تتيح للطالب:
- تنظيم مهامه الدراسية وتحديد مواعيدها وحالتها.
- متابعة نسبة إنجازه عبر لوحة إحصائيات فورية (إجمالي المهام، المكتملة، قيد التنفيذ).
- الوصول الآمن والمحمي لبياناته الخاصة مع واجهة عربية تفاعلية متجاوبة (RTL).

تم إعداد وتأسيس هذا المشروع باتباع أفضل الممارسات الهندسية التي تسبق وترافق كتابة الكود: هندسة المتطلبات، وثيقة Mini-SRS، تقسيم العمل وتحديد قصص المستخدم، إدارة سير العمل عبر لوحة Kanban، والالتزام الصارم بدورة عمل Git/GitHub الاحترافية.

## 👥 أعضاء الفريق والأدوار (Team Members & Roles)

| الاسم | الدور الأساسي | المسؤوليات |
|---|---|---|
| **طالب 1 (AWMO-1)** | **Team Coordinator & Repo Maintainer** | إدارة المستودع، ضبط الفروع، وتنسيق سير العمل على لوحة Kanban |
| **طالب 2** | **Requirements Owner** | صياغة وتوثيق وثيقة SRS، قصص المستخدم، ومعايير القبول |
| **طالب 3** | **Lead Developer** | كتابة وتنفيذ نماذج ومسارات ومتحكمات النظام |
| **طالب 4** | **QA & Reviewer** | مراجعة الكود (Code Review)، فحص حالات الحافة، وضبط جودة الـ Pull Requests |

*(ملاحظة: في الفرق الفردية أو المصغرة، يتولى الطالب قيادة الأدوار المذكورة بالكامل وفق المنهجية الهندسية).*

1. **[وثيقة المتطلبات البرمجية المصغرة (Mini-SRS)](file:///docs/SRS.md)**: تحتوي على 5 متطلبات وظيفية، 3 متطلبات غير وظيفية، والنطاق، وحالات الحافة.

## 🔄 دورة العمل الهندسية المعتمدة (Workflow)

```text
متطلب في SRS (Requirement)
       ↓
إنشاء Issue في GitHub Project (To Do)
       ↓
إنشاء فرع مستقل: type/issue-number-short-description
       ↓
تنفيذ التعديلات (Code / Documentation)
       ↓
Commit مع رسالة وصفية واضحة
       ↓
Push إلى GitHub
       ↓
فتح Pull Request وربطه بالـ Issue (Closes #X)
       ↓
مراجعة الكود (Code Review) بواسطة زميل
       ↓
الدمج إلى الفرع الرئيسي (Merge to main)
       ↓
إغلاق الـ Issue ونقلها إلى Done
```
