# توزيع الأدوار والمسؤوليات الهندسية — Team Roles & Responsibilities

> استناداً إلى معايير المحاضرة الأولى، يتم تقسيم العمل الهندسي بين أعضاء الفريق لضمان المساءلة والتعاون المنظم.

---

## 1. قائد الفريق ومنسق العمل (Team Coordinator)
* **المسؤول:** AWMO-1
* **المسؤوليات:**
  - متابعة سير العمل العام وتوزيع المهام على الأعضاء.
  - إدارة لوحة المشروع (Kanban Board) وتحديث حالة الـ Issues بين الأعمدة.
  - إزالة أي عقبات تقنية أو تواصلية تعيق تقدم الفريق.
  - التأكد من التزام الفريق بالخطة الزمنية المعتمدة للمقرر.

---

## 2. مسؤول المتطلبات والتوثيق (Requirements Owner)
* **المسؤوليات:**
  - قيادة إعداد وتحديث وثيقة متطلبات البرمجيات المصغرة (`docs/SRS.md`).
  - صياغة قصص المستخدم (User Stories) وفق المعيار الدولي المعتمد.
  - تحديد معايير القبول (Acceptance Criteria) بصيغة `Given-When-Then`.
  - اكتشاف وتوثيق حالات الحافة (Edge Cases) وإدراجها في خطط العمل.

---

## 3. مسؤول المستودع وضبط الجودة (Repository Maintainer)
* **المسؤوليات:**
  - تهيئة المستودع وضبط ملف `.gitignore` لمنع رفع أي بيانات حساسة أو أسرار.
  - ضبط استراتيجية الفروع وحماية الفرع الرئيسي `main`.
  - التحقق من التزام الـ Commits بالتسميات القياسية.
  - إدارة عمليات الدمج (Merge) بعد اكتمال المراجعة.

---

## 4. المطورون (Developers)
* **المسؤوليات:**
  - إنشاء الفروع المنفصلة لكل مهمة بصيغة: `type/issue-number-short-description`.
  - تنفيذ الكود أو التوثيق المطلوب بدقة ودون أي إضافات غير مطلوبة.
  - فحص التغييرات محلياً ومراجعة `git diff`.
  - كتابة رسائل Commit واضحة ووصفية.
  - رفع التعديلات وفتح الـ Pull Requests وربطها بالـ Issue المعنية (`Closes #X`).

---

## 5. المراجع وضابط الجودة (Reviewer / QA)
* **المسؤوليات:**
  - فحص الـ Pull Request ومقارنته بمعايير القبول لقصة المستخدم.
  - التأكد من عدم إدخال أخطاء أو كسر وظائف سابقة.
  - كتابة تعليقات مراجعة بناءة ومحددة وقابلة للتنفيذ (تجنب التعليقات الشكلية مثل "جيد").
  - منح الموافقة (Approve) أو طلب تعديلات (Request Changes) قبل دمج الكود.
