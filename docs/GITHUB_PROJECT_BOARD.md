> وفقاً لتعليمات المحاضرة الأولى (القسم 11 والقسم 17)، تم تصميم لوحة Kanban لتتبع سريان العمل بصرياً وتجنب تراكم المهام في عمود واحد.

---

## 1. هيكل الأعمدة الخمسة المعتمدة (Kanban Columns)

```text
[ 1. Backlog ] ──► [ 2. Ready ] ──► [ 3. In Progress ] ──► [ 4. In Review ] ──► [ 5. Done ]
```

1. **Backlog (قائمة الأعمال العامة):** الأفكار والمتطلبات المستقبلية التي لم يتم تجهيزها أو تقدير وقتها بعد.
2. **Ready (جاهزة للتنفيذ):** مهام محددة بدقة، ولها قصة مستخدم واضحة ومعايير قبول وحالات حافة، ويمكن لأي مطور البدء بها فوراً.
3. **In Progress (قيد التنفيذ):** المهام التي يعمل عليها أحد أعضاء الفريق فعلياً في فرع (Branch) مستقل.
4. **In Review (قيد المراجعة):** المهام التي اكتمل كودها وتم فتح Pull Request لها وهي بانتظار مراجعة الزميل وضابط الجودة.
5. **Done (المكتملة):** المهام التي تم استيفاء معايير قبولها واختبارها ومراجعتها ودمجها في `main` وإغلاق الـ Issue الخاصة بها.

## 3. معايير نقل المهام بين الأعمدة (Definition of Done & Transitions)

- **من Ready إلى In Progress:** عندما يقوم المطور بعمل Assign لنفسه وإنشاء فرع باسم `feature/issue-X-...`.
- **من In Progress إلى In Review:** عند رفع الكود وفتح Pull Request بصيغة واضحة وربطه بالـ Issue بكلمة `Closes #X`.
- **من In Review إلى Done:** لا تُنقل المهمة إلى Done إلا بعد:
  - [x] تحقق واختبار معايير القبول فعلياً.
  - [x] مراجعة الكود من قبل زميل (Peer Review) والموافقة عليه (Approve).
  - [x] دمج الـ Pull Request إلى فرع `main`.
  - [x] إغلاق الـ Issue تلقائياً.
