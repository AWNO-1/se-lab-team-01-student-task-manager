## Issue #1: User Registration and Secure Authentication
* **Labels:** `authentication`, `security`, `high-priority`
* **Assignee:** Lead Developer
* **Related Requirement:** `FR-01`, `NFR-01`

### User Story
بصفتي طالباً جامعياً،
أريد إنشاء حساب جديد وتسجيل الدخول بأمان إلى النظام،
حتى أتمكن من إدارة ومتابعة مهامي الدراسية الخاصة بي دون اطلاع الآخرين عليها.

### Description
توفير نظام مصادقة متكامل يشمل صفحات التسجيل والدخول والخروج، وتشفير كلمات المرور وحماية الجلسة، وحظر وصول الزوار غير المسجلين إلى مسارات المهام.

### Acceptance Criteria
- [ ] **Given** مستخدم غير مسجل، **When** يملأ استمارة التسجيل ببيانات صحيحة ويضغط تأكيد، **Then** يتم إنشاء الحساب وتشفير كلمة المرور وتوجيهه إلى لوحة التحكم.
- [ ] **Given** مستخدم يدخل بريداً إلكترونياً مستخدماً مسبقاً، **When** يضغط تسجيل، **Then** يرفض النظام وتظهر رسالة خطأ واضحة تفيد بأن البريد مستخدم.
- [ ] **Given** زائر غير مسجل، **When** يحاول فتح الرابط `/tasks` مباشرة، **Then** يتم توجيهه تلقائياً إلى صفحة تسجيل الدخول `/login`.

### Edge Cases
- إدخال كلمة مرور قصيرة أقل من الحد الأدنى المسموح.
- إدخال بريد إلكتروني بصيغة غير صحيحة.

### Definition of Done
- [ ] نجاح اختبارات الدخول والخروج.
- [ ] تشفير كلمات المرور في قاعدة البيانات.
- [ ] وجود حماية CSRF على كافة النماذج.

## Issue #2: Allow Students to Create New Tasks with Validation
* **Labels:** `feature`, `tasks`, `high-priority`
* **Assignee:** Developer
* **Related Requirement:** `FR-02`, `EC-DATA-01`

### User Story
بصفتي طالباً،
أريد إنشاء مهمة دراسية جديدة بعنوان وتفاصيل واضحة،
حتى أتمكن من توثيق الواجبات المطلوبة مني وعدم نسيانها.

### Description
بناء صفحة ونموذج إضافة مهمة جديدة تتضمن حقلي العنوان والوصف وصندوق حالة الإنجاز، مع التحقق الصارم عبر Form Request وتخزين السجل في قاعدة البيانات.

### Acceptance Criteria
- [ ] **Given** طالب مسجل الدخول في صفحة `/tasks/create`، **When** يدخل عنواناً ووصفاً صالحين ويضغط حفظ، **Then** يتم حفظ المهمة وتحويله لصفحة تفاصيلها مع رسالة نجاح.
- [ ] **Given** طالب يترك حقل العنوان فارغاً، **When** يضغط زر الحفظ، **Then** يرفض الخادم الطلب ويظهر رسالة: *يرجى كتابة عنوان المهمة.*
- [ ] **Given** طالب يدخل وصفاً أطول من 1000 حرف، **When** يحاول الحفظ، **Then** يرفض الخادم ويظهر رسالة: *يجب ألا يزيد وصف المهمة على 1000 حرف.*

### Edge Cases
- إدخال عنوان مكون من مسافات بيضاء فقط.
- النقر المزدوج السريع على زر الحفظ (منع تكرار الإرسال).

### Definition of Done
- [ ] فئة `StoreTaskRequest` تعمل وتتحقق من البيانات.
- [ ] نموذج Blade يظهر رسائل الأخطاء العربية بجانب الحقول.
- [ ] احتفاظ الحقول بمدخلاتها القديمة عند الفشل عبر `old()`.

## Issue #3: Tasks Index Dashboard with Statistics and Pagination
* **Labels:** `feature`, `ui/ux`, `high-priority`
* **Assignee:** Developer
* **Related Requirement:** `FR-03`, `NFR-02`

### User Story
بصفتي طالباً،
أريد استعراض لوحة تحكم تعرض كافة مهامي مع ملخص إحصائي لحالاتها وترقيم للنتائج،
حتى أتمكن من أخذ نظرة شاملة وسريعة على حجم الإنجاز المتبقي عليّ.

### Description
بناء صفحة الفهرس الرئيسية `/tasks` لعرض 3 بطاقات إحصائية (إجمالي، مكتمل، قيد التنفيذ)، وشبكة بطاقات متجاوبة للمهام مع شارات ملونة للحالة، وترقيم الصفحات بمعدل 9 مهام بكل صفحة.

### Acceptance Criteria
- [ ] **Given** طالب لديه 15 مهمة (10 مكتملة و5 قيد التنفيذ)، **When** يفتح صفحة `/tasks`، **Then** تعرض بطاقات الإحصاء: 15 إجمالي، 10 مكتملة، 5 قيد التنفيذ بدقة.
- [ ] **Given** طالب لديه أكثر من 9 مهام، **When** يستعرض الصفحة، **Then** يظهر ترقيم الصفحات (Pagination) أسفل الشبكة للانتقال بينها بسلاسة.
- [ ] **Given** مستخدم جديد ليس لديه أي مهام، **When** يفتح الصفحة، **Then** تظهر شاشة حالة فارغة (Empty State) تشجعه على إنشاء أول مهمة.

### Edge Cases
- تغير عدد المهام الإجمالي أثناء التصفح (دقة الحساب).
- ظهور النصوص الطويلة في بطاقة المهمة دون كسر تخطيط الواجهة.

### Definition of Done
- [ ] استخدام استعلامات كفؤة عبر `paginate(9)` و `count()`.
- [ ] توافق العرض الكامل مع الهواتف والشاشات الصغيرة.

## Issue #4: Edit Task and Toggle Completion Status
* **Labels:** `feature`, `tasks`, `medium-priority`
* **Assignee:** Developer
* **Related Requirement:** `FR-04`, `EC-DATA-03`

### User Story
بصفتي طالباً،
أريد تعديل بيانات مهمة موجودة أو تعليمها كمكتملة،
حتى تظل قائمة مهامي محدثة وتعكس وضعي الدراسي الفعلي.

### Description
بناء صفحة تعديل المهمة `/tasks/{task}/edit` باستخدام نموذج Blade الجزئي المشترك، وإتاحة تحديث الحقول أو تبديل حالة الإنجاز عبر صندوق الاختيار، وإرسال طلب `PUT` الآمن.

### Acceptance Criteria
- [ ] **Given** طالب يفتح صفحة تعديل مهمة، **When** يغير العنوان ويحدد صندوق الإنجاز ويضغط حفظ، **Then** يتم تحديث السجل وحالته وتوجيهه لصفحة التفاصيل مع رسالة نجاح.
- [ ] **Given** طالب يلغي تحديد صندوق الإنجاز لمهمة مكتملة، **When** يضغط حفظ، **Then** تصبح حالة المهمة غير مكتملة (قيد التنفيذ) وتتحدث الإحصائيات فوراً.

### Edge Cases
- إرسال النموذج عند إلغاء تحديد الـ Checkbox والتأكد من استقبال القيمة `0`.
- محاولة تعديل مهمة بمعرف غير موجود وإرجاع 404 تلقائياً.

### Definition of Done
- [ ] استخدام فئة `UpdateTaskRequest`.
- [ ] استخدام توجيه `@method('PUT')` داخل النموذج.

## Issue #5: Delete Task with Safety Confirmation
* **Labels:** `feature`, `tasks`, `medium-priority`
* **Assignee:** Developer
* **Related Requirement:** `FR-05`, `NFR-03`

### User Story
بصفتي طالباً،
أريد حذف مهمة انتهيت منها ولم أعد بحاجة إليها مع تأكيد الحذف،
حتى أحافظ على قائمة مهامي نظيفة دون خوف من الحذف العرضي الخاطئ.

### Description
إتاحة زر الحذف في صفحتي القائمة والتفاصيل مع ربطه بطلب `DELETE` محمي برمز CSRF ونافذة تأكيد تنبيهية لمنع الحذف غير المقصود.

### Acceptance Criteria
- [ ] **Given** طالب ينقر على زر الحذف لمهمة، **When** تظهر نافذة التأكيد ويضغط "موافق"، **Then** يتم حذف المهمة نهائياً من قاعدة البيانات وإعادته للقائمة مع رسالة نجاح.
- [ ] **Given** طالب ينقر على زر الحذف، **When** يضغط "إلغاء" في نافذة التأكيد، **Then** يتم إلغاء الإجراء وتبقى المهمة دون تغيير.

### Edge Cases
- محاولة حذف مهمة تم حذفها بالفعل في لسان متصفح آخر وإرجاع استجابة آمنة.

### Definition of Done
- [ ] استخدام توجيه `@method('DELETE')` وحماية `@csrf`.
- [ ] تمييز زر الحذف باللون الأحمر الدلالي للتحذير.
